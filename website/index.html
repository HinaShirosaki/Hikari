Cross-linked by design

One entry pulls in the whole bench

Start an experiment from a protocol and Hikari snapshots the protocol text that was actually run. From there the record can carry a sample, a reagent lot, an assay plate, a gel lane table and a paper — each one read live from the module that owns it.

Result tables use the same spreadsheet formula engine as Assay, and the finished entry exports to PDF with its tables and previews intact.

Data and storage

One folder. You can see it in Finder.

You set a storage root once. Every heavy file — notebook attachments, papers, assay artifacts, gel images, sequence assets — lands under it, beside a single .json/.ena snapshot of the records themselves.

That makes backup a folder copy, sharing a file, and inspection a text editor. Large inventories stay fast through an on-disk index. Nothing leaves the machine unless you ask it to.

Set Settings › Storage first: auto-save stays off until the root folder is chosen.
# your storage root
lab-data/
├─ enana-data.ena.json   # every record, one snapshot
├─ notebook/             # entry attachments + page log
├─ papers/               # PDFs, comments, summaries
├─ assay/                # analysis JSON, chart SVG
├─ gels/                 # gel images and reports
└─ sequences/            # imported sequence assets
Plugins

Extra workspaces, in a sandbox

Plugin workspaces run in a sandboxed iframe with a declared permission list and appear behind the dock's More button.

Gel ships bundled: TIFF ingestion, crop and free rotation, lane segmentation, ladder calibration, band quantification and peak editing, plus PNG export at up to 4× density and PowerPoint export that keeps the lane table as an editable native table.

Gel asks for four permissions

And gets nothing else — no notebook, project, sample or protocol access.

Quick start

Running in two commands

Needs Node.js 20+ and npm. macOS, Windows and Linux.

npm install
npm run start
  1. Set the storage root. Settings › Storage — do this before anything else.
  2. Pick a startup module, or let Hikari remember the last one you opened.
  3. Fill in your vocabularies — storage locations and sample type names in Settings.
  4. Sign in to the codex CLI if you want the Agent, paper summaries or protocol drafting.
