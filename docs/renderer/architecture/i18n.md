# Incremental renderer i18n

> Coverage update (2026-10-29): app-owned renderer UI, shared surfaces,
> first-party plugin interfaces and native dialog copy use English-first catalogs.
> See [the current audit](i18n-audit.md) for boundaries and verification.

Settings → Appearance → Language offers **English** and **Español (preview)**.
The existing Save changes / Discard flow applies to this preference. Saving
updates the current UI without reloading or recreating modules and persists
`settings.locale` for the next launch. English remains the default for existing
workspaces without a preference. Unsupported or malformed locales fall back to
English; Spanish regional locales resolve to `es`.

Spanish catalogs are bundled beside the English files as `locales/es.js`.
Untranslated entries use the English catalog, and the setting explains the
preview status. Tests use these production catalogs as shipped. The layer
adds no translation requests, browser-language detection, mutation observer, or
asynchronous catalog loading.

## Ownership

- `src/renderer/lib/i18n/locale.js`: product locale allowlist and normalization.
- `src/renderer/lib/i18n/runtime.js`: independent translator instances, message
  registration, locale/English fallback, interpolation, plural selection,
  `Intl` number/date formatting, and disposable locale subscriptions.
- `src/renderer/lib/i18n/index.js`: the shared renderer instance and `t()`.
- `src/renderer/lib/i18n/{en,es}.js`: common action and form-status copy.
- `src/renderer/lib/i18n/dom.js`: opt-in text and attribute bindings.
- `src/renderer/lib/i18n/markup.js`: escaped, bound spans for generated UI labels.
- `src/renderer/app/localization.js`: document language and translation refresh
  at startup, after workspace hydration/replacement, on save and on history restoration;
  it also synchronizes native dialog language through `system:set-ui-locale`.

Feature catalogs stay in `modules/<feature>/locales/{en,es}.js` and register under
their own namespace before the feature renders. The shared layer never imports
feature modules. Native dialogs and plugin frames have their own bundled catalogs;
plugins receive the active locale in app-context events. OS-owned menus, exported
document contents, persisted user content and agent prompts keep their existing contracts.

## Migrate the next module

1. Move UI copy into a flat English catalog with stable semantic keys. Leave
   record names, IDs, form values, protocol text, units, and user content alone.
2. Register the catalog when the module loads:

   ```js
   import { i18n } from '../../lib/i18n/index.js';
   import { moduleEnglish } from './locales/en.js';
   i18n.registerMessages('en', 'my-module', moduleEnglish);
   const t = i18n.scope('my-module');
   ```

3. Mark static leaf text with `data-i18n="my-module.empty.title"`, leaving its
   English text in place. Use `data-i18n-title`, `data-i18n-placeholder`,
   `data-i18n-aria-label`, or `data-i18n-alt` for attributes. Call
   `translateTree(moduleRoot)` after creating dynamic markup.
   `data-i18n-aria-valuetext` covers progress-bar value descriptions.
   `data-i18n-hover-caption` covers the app's hover-caption attribute.
   `data-i18n-caption` binding supplies `data-caption` for CSS-generated captions.
   `data-i18n-label` covers `<optgroup label>`.
   A `data-i18n-params` JSON object supplies string/number/boolean placeholders to
   both text and attributes; invalid or nested parameter objects preserve the
   existing content. When cloning a numbered row, update its `index` parameter.
4. Use `t('key', { name })` for dynamic plain text. Interpolation uses `{name}`
   placeholders; missing parameters remain visible. Plural messages are objects
   such as `{ one: '{count} item', other: '{count} items' }`. Pass a numeric
   `count`; plural rules follow the language of the message actually found.
5. For a module that needs to rebuild dynamic text when the locale changes,
   subscribe its own lightweight refresh and retain the returned unsubscribe
   callback. Avoid calling the application's `renderAll()` from that listener;
   locale changes must preserve active editing and unrelated module state.
6. Check English parity and the module's existing interactions before moving
   on to another module.

`t('namespace.key', params, 'Original English')` supports an explicit fallback;
otherwise an unknown key is returned for diagnosis. DOM bindings preserve
existing text/attributes when a key is unknown. Regional locales fall back to
their parent catalogs, then English.

Catalogs are plain text, never HTML. Assign translations with `textContent` or
escape them at the HTML output boundary. Do not put `data-i18n` on containers:
the helper intentionally skips elements with child elements, editable content,
form fields, and options without explicit values. It changes neither input
values nor handlers, selection, focus, or routing IDs. Attribute bindings use a
fixed allowlist and cannot target URLs, event handlers, or form values.

Use `messageSpan('namespace.key', params)` for escaped labels in generated
markup and `setTranslatedText(element, 'namespace.key', params)` for a plain
status/result element. They preserve bindings for later locale switches. Clear
the `data-i18n` binding when replacing a UI fallback with user content. Likewise,
remove a translated placeholder binding when replacing `auto` with a calculated
quantity, so a later locale switch cannot overwrite the calculation.

`messageAttributes()` accepts only the same fixed attribute allowlist as the DOM
bindings. `setTranslatedAttribute()` merges parameters, retaining a row's index
when a computed placeholder adds quantity parameters. `dateSpan()` binds an ISO
date plus formatting options and the original English/OS fallback without
rebuilding the parent element.

## Add a language later

Bundle its common and migrated feature catalogs before selecting it. Register
those catalogs and add its canonical BCP 47 tag to `SUPPORTED_LOCALES`, then
provide a Settings control that persists `state.settings.locale` and refreshes
the locale without rerendering unrelated modules. Incomplete feature catalogs
fall back to English. Product language selection, RTL layout, main-process
menus, plugin localization, and export-language policy remain separate work.
